# 投稿审核与浏览量后台

后台地址：`https://schemer.online/admin`。

后台包含独立的投稿审核队列和浏览量统计。投稿按状态筛选，每页 20 条，支持前后翻页，历史投稿不会因超出最近 50 条而无法查阅。浏览量按北京时间统计每日页面打开次数（PV），不是独立访客数；重复打开页面会重复计数，不补算上线前访问。

## 投稿处理闭环

1. 访客填写称呼（可用昵称）和事件，取得私密回执。回执由浏览器生成；同一回执与相同内容重试不会重复入库。
2. 管理员查看原文，设置“待查看 / 核查中 / 待整理发布 / 已收录或更新 / 已处理 / 暂不收录”。
3. 投稿不会自动发布。需要收录时，先在内容仓库完成编辑、校验、发布，再选择“已收录 / 更新”并填写已公开档案路径。
4. 服务端只允许 `/events/…`、`/people/…`、`/organizations/…` 路径，并核对当前 `/published-entries.json`。不存在、未公开或站外链接不能标记为已收录。
5. “已处理”和“暂不收录”必须有处理说明。说明会向持有回执的人展示，请勿写入个人敏感信息或内部备注。
6. 状态、说明、关联路径的每次保存均产生管理员处理历史；并发修改使用版本校验，过期版本返回冲突而不会覆盖他人结果。

访客在 `/submit` 的查询区输入回执即可查看状态、处理说明与档案链接。查询接口使用 POST，不将回执放入 URL；不返回称呼、投稿原文或后台处理历史。数据库仅保存回执哈希。若关联档案后来撤回，查询会隐藏该链接并保留处理记录。旧投稿没有回执，继续在后台可查可处理，不能为其补造访客凭证。

后台未保存的处理草稿仅保留在当前页面内存，刷新队列、筛选、重新登录时可恢复；主动退出会清除草稿。浏览器离页或退出时会提示存在未保存改动。

## 配置与运行

见 [SUBMISSIONS_SETUP.md](SUBMISSIONS_SETUP.md)。统计和投稿共用 D1 绑定 `ANALYTICS_DB`。首次安装需要按顺序应用 `0001` 和 `0002`；旧库只需新增的 `0002`，不能重复执行该迁移。

Astro 页面静态生成，仅 `/api/*` 由 Cloudflare Pages Functions 处理。`npm run dev` 只启动 Astro，不提供投稿、登录或 D1；完整闭环应使用隔离本地数据库的 Pages Functions 预览。

统计只保存日期、页面路径和浏览次数，不记录访客 IP、Cookie 或浏览器信息。后台登录另使用 8 小时有效的 HttpOnly Cookie。投稿保存称呼、事件、回执哈希、时间、处理状态与处理历史；不会自动进入公开网页或 Git 仓库。
